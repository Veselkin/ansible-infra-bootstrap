# Плейбуки Ansible для базовой настройки сервера

В этом каталоге содержатся два плейбука, которые автоматизируют начальную конфигурацию серверов:

* **`setup-time.yaml`** — установка и настройка синхронизации времени (Chrony) и временной зоны.
* **`secure-server.yaml`** — базовая защита: настройка файрвола (UFW) и системы обнаружения вторжений (Fail2ban).

## Требования

* Ansible версии **2.9** или выше.
* Целевые хосты должны быть доступны по SSH с правами **sudo** (`become: yes`).
* Для `secure-server.yaml` требуется **Debian/Ubuntu** (используются `apt` и `ufw`).
* Для `setup-time.yaml` поддерживаются как Debian, так и Red Hat-подобные системы (учитываются различия в имени службы).

## Использование

Общий формат запуска:

```bash
ansible-playbook -i <инвентарный_файл> <имя_плейбука>.yaml [-e "переменная=значение"]
```

Пример с инвентарём `hosts.ini`:

```bash
ansible-playbook -i hosts.ini setup-time.yaml
```

# Плейбук `setup-time.yaml`

## Назначение

Установка пакета `chrony`, настройка временной зоны, запуск и включение службы синхронизации, а также принудительная синхронизация времени.

## Переменные

| Имя                 | По умолчанию    | Описание                                            |
| ------------------- | --------------- | --------------------------------------------------- |
| `selected_timezone` | `Europe/Samara` | Желаемая временная зона (в формате TZ-базы данных). |

## Задачи

1. Установка пакета `chrony`.
2. Установка временной зоны через модуль `timezone`.
3. Запуск и включение службы `chrony` (имя определяется по `ansible_os_family`).
4. Принудительный шаг синхронизации (`chronyc makestep`) для немедленного применения.

## Обработчики

Перезапуск службы `chrony` при изменении конфигурации.

В данном плейбуке обработчик срабатывает, если служба была включена или запущена, но фактический перезапуск происходит только при необходимости.

## Пример запуска с другой временной зоной

```bash
ansible-playbook -i production setup-time.yaml -e "selected_timezone=Europe/Moscow"
```

# Плейбук `secure-server.yaml`

## Назначение

Базовая защита сервера: настройка файрвола (UFW) и установка Fail2ban для предотвращения брутфорс-атак на SSH.

## Переменные

| Имя                    | По умолчанию | Описание                                                     |
| ---------------------- | -----------: | ------------------------------------------------------------ |
| `ssh_port`             |         `22` | Порт SSH                                                     |
| `additional_tcp_ports` |  `[80, 443]` | Список дополнительных TCP-портов                             |
| `additional_udp_ports` |      `[443]` | Список дополнительных UDP-портов (например, для QUIC/HTTP/3) |

## Задачи

### Установка пакетов

Устанавливаются пакеты:

* `ufw`;
* `fail2ban`.

### Настройка UFW

Настраиваются политики UFW по умолчанию:

* **incoming — deny** — запретить все входящие соединения;
* **outgoing — allow** — разрешить все исходящие соединения.

После этого:

* разрешается входящее TCP-соединение на порт `ssh_port`;
* разрешаются TCP-порты из списка `additional_tcp_ports`, если список не пуст;
* разрешаются UDP-порты из списка `additional_udp_ports`, если список не пуст;
* UFW включается после добавления правила для SSH.

### Настройка Fail2ban

Создаётся файл `/etc/fail2ban/jail.local` со следующими параметрами:

```ini
bantime = 3600
findtime = 600
maxretry = 5
```

Где:

* `bantime = 3600` — бан на один час;
* `findtime = 600` — окно наблюдения 10 минут;
* `maxretry = 5` — пять неудачных попыток.

Также включается защита `sshd` с указанием порта `ssh_port`.

Служба `fail2ban` запускается и добавляется в автозагрузку.

## Обработчики

**`restart fail2ban`** — перезапуск Fail2ban после изменения конфигурации.

## Важно

Перед запуском убедитесь, что переменная `ssh_port` соответствует реальному порту SSH на целевых серверах.

Если вы меняете порт SSH, не забудьте указать его в инвентаре Ansible, например через `ansible_ssh_port`, либо используйте параметр `--ssh-common-args`.

## Примеры запуска

### Кастомные списки TCP- и UDP-портов

```bash
ansible-playbook -i inventory secure-server.yaml \
  -e "additional_tcp_ports=[80,443,8080] additional_udp_ports=[443,51820]"
```

### Если UDP-порты не нужны

Передайте пустой список:

```bash
ansible-playbook -i inventory secure-server.yaml \
  -e "additional_udp_ports=[]"
```

## Примечания

* Для `secure-server.yaml` требуется система на основе Debian/Ubuntu, так как используются модули `apt` и `ufw`.
* Для `setup-time.yaml` совместимость шире: он работает как на Debian, так и на Red Hat-подобных системах (CentOS/RHEL), поскольку использует общие модули `package`, `service` и `timezone`.
* После применения `secure-server.yaml` проверьте доступность SSH в новом окне терминала, чтобы избежать блокировки.
* Если вы используете разные порты для разных хостов, рекомендуется задавать переменные либо в инвентаре (групповые/хостовые переменные), либо через `-e` при запуске.
