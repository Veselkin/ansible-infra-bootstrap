# Ansible Infrastructure Control

Репозиторий содержит инструменты для автоматической подготовки серверов и управления их конфигурацией через Ansible.

## Структура

* `scripts/bootstrap.sh` — универсальный скрипт для первичной настройки сервера.
* `inventory/` — файлы инвентаря (списки хостов).
* `group_vars/` — переменные для групп хостов.
* `playbooks/` — сценарии Ansible.
* `ansible.cfg` — локальные настройки Ansible.

## Требования к управляющей машине

Перед запуском `bootstrap.sh` убедитесь, что установлены:

* **Ansible** и **Git** — для дальнейшей работы.
* **sshpass** — утилита для автоматического ввода пароля при SSH-подключении.

### Установка

**Debian / Ubuntu:**

```bash
sudo apt update && sudo apt install -y ansible git sshpass
```

**CentOS / RHEL:**

```bash
sudo yum install -y ansible git sshpass
```

**macOS (через Homebrew):**

```bash
brew install ansible git sshpass
```

## Подготовка сервера через `bootstrap.sh`

`scripts/bootstrap.sh` выполняет полную настройку сервера для последующего управления через Ansible.

Скрипт работает в два этапа: сначала создаёт пользователя и ключ (парольный вход ещё активен), затем, после вашего подтверждения, отключает парольный вход.

### Запуск

```bash
./scripts/bootstrap.sh
```

### Интерактивный ввод

Скрипт запросит:

* **IP-адрес** сервера;
* **логин** для первоначального подключения (обычно `root`);
* **пароль** текущего пользователя;
* **имя нового пользователя** для Ansible (по умолчанию `sysops`).

> Вы можете указать уникальное имя пользователя для каждого сервера — например, `sysops-prod` или `sysops-staging`. Это повышает безопасность и упрощает аудит. Если имя не указано, будет использован `sysops` для всех серверов.

### Что делает скрипт

**Перед началом** скрипт выполняет проверки и выводит их результат:

* наличие необходимых утилит (`sshpass`, `ssh`, `scp`, `ssh-keygen`);
* доступность порта 22 на сервере;
* возможность подключения по SSH с введённым логином и паролем.

Если какая-либо проверка не проходит, скрипт завершается с сообщением об ошибке.

**Если скрипт запущен повторно** и сервер уже настроен (ключ для указанного пользователя существует и подключение по нему работает), скрипт выведет сообщение `✅ Сервер уже настроен. Выход.` и завершится без изменений.

**Далее:**

1. **Генерирует SSH-ключи** (если их нет) и сохраняет их в `~/.ssh/<имя_пользователя>`.
2. **Копирует и запускает на сервере** скрипт создания пользователя:

   * создаёт указанного пользователя;
   * добавляет его в группу `sudo` (или `wheel`);
   * настраивает `NOPASSWD` в sudoers;
   * добавляет публичный ключ в `~/.ssh/authorized_keys`.
3. **Проверяет подключение по ключу** — если не работает, скрипт останавливается.
4. **Выводит приватный ключ в терминал** и просит подтвердить, что он сохранён:

   * показывает путь к ключу на текущей машине;
   * печатает содержимое приватного ключа;
   * подсказывает, как перенести ключ на другой компьютер (вручную или через `scp`);
   * запрашивает подтверждение `yes/no` перед отключением парольного входа.

   При ответе `no` настройка SSH не выполняется: парольный вход остаётся активным, а ключ уже работает.
5. **Настраивает SSH** на сервере:

   * отключает парольную аутентификацию;
   * разрешает только вход по ключам;
   * разрешает вход только для указанного пользователя (`AllowUsers`);
   * устанавливает таймауты сессий (`ClientAliveInterval`, `ClientAliveCountMax`);
   * отключает `PermitRootLogin` (заменяет на `prohibit-password`).
6. **Перезагружает SSH** без разрыва текущих сессий.
7. **Проверяет итоговое подключение** — если всё успешно, сервер готов.

После выполнения скрипта вы сможете подключаться к серверу как новый пользователь по SSH-ключу:

```bash
ssh -i ~/.ssh/<имя_пользователя> <имя_пользователя>@<IP-адрес>
```

## Безопасность SSH-ключей

По умолчанию скрипт создаёт отдельный приватный ключ для каждого уникального имени пользователя на сервере. Если ключ уже существует, он переиспользуется, и скрипт пишет «Ключ уже существует». Поэтому при одинаковом имени (например, `sysops` по умолчанию) ключ будет общим, а для нового имени создаётся новый.

Для повышения безопасности рекомендуется:

* хранить приватный ключ в защищённом месте;
* использовать `ssh-agent` для ограничения времени доступа;
* при необходимости генерировать отдельные ключи для каждого сервера.

Также вы можете использовать **уникальные имена пользователей** для разных серверов — тогда ключи будут сохраняться как `~/.ssh/<имя_пользователя>`, что естественным образом изолирует доступ.

### Вывод приватного ключа

Перед отключением пароля скрипт печатает приватный ключ в терминал открытым текстом. Поэтому:

* не запускайте скрипт при записи экрана, трансляции или в общей tmux/screen-сессии;
* не запускайте под `script` или с логированием вывода — ключ попадёт в лог;
* после сохранения ключа очистите экран и scrollback: `clear && printf '\e[3J'`;
* копируйте ключ целиком, включая строки `-----BEGIN ...-----` и `-----END ...-----`;
* если скрипт запущен на удалённой машине по SSH, ключ проходит по каналу — надёжнее забрать файл через `scp`, а не копировать из терминала.

## Проверка и запуск Ansible

### Проверка доступности серверов

```bash
ansible all -m ping
```

### Запуск плейбуков

```bash
ansible-playbook playbooks/setup_time.yml
```

## Безопасность и рекомендации

* **Секреты** — шифруйте конфиденциальные данные с помощью `ansible-vault`.
* **NOPASSWD** — настраивается автоматически, поэтому Ansible не будет прерываться запросом пароля.
* **Проверка ключей хостов** — в `ansible.cfg` отключена (`host_key_checking = False`), чтобы избежать ошибок при первом подключении.
