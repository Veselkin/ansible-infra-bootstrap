# Ansible Infrastructure Control
Репозиторий для автоматизации настройки серверов. Содержит инструменты для первичной подготовки узлов (Bootstrap) и управления конфигурациями.
---
## Структура проекта
- scripts/ — Bash-скрипты для «холодной» подготовки серверов (создание пользователя, настройка sudo).

- inventory/ — Списки ваших серверов (hosts).

- group_vars/ — Переменные, разбитые по группам хостов.

- playbooks/ — Сценарии автоматизации.

- ansible.cfg — Локальные настройки Ansible (приоритетнее системных).
---
## Быстрый старт
***1. Подготовка управляющей машины (Local PC)***
Убедитесь, что у вас установлен Ansible и Git:
```
sudo apt update && sudo apt install -y ansible git
```
Сгенерируйте SSH-ключ для работы Ansible (если он не был создан ранее):

```
ssh-keygen -t ed25519 -f ~/.ssh/sysops -C "ansible_key" -N ""
```
***2. Подготовка удаленного сервера (Bootstrap)***
Перед тем как Ansible сможет управлять сервером, там должен быть создан пользователь sysops.

### Скопируйте скрипт подготовки на сервер:

```
scp scripts/setup_sysops.sh root@<REMOTE_IP>:/tmp/
```
### Запустите скрипт под root:

```
ssh root@<REMOTE_IP> "bash /tmp/setup_sysops.sh"
```
### Передайте SSH-ключ:

```
ssh-copy-id -i ~/.ssh/sysops sysops@<REMOTE_IP>
```

## Использование Ansible
### Проверка связи
Перед запуском плейбуков всегда проверяйте доступность узлов:

```
ansible all -m ping
```

### Запуск плейбуков
Для выполнения сценария используйте:

```
ansible-playbook playbooks/site.yml
```

Совет: Если нужно проверить, что сделает скрипт, не внося реальных изменений, добавьте флаг --check.

## Безопасность и Best Practices
- Конфиденциальность: Никогда не фиксируйте в Git открытые пароли или API-ключи. Используйте ansible-vault:

```
# Шифрование файла с секретами
ansible-vault encrypt group_vars/all/secrets.yml
```

- Sudo: Настройка NOPASSWD в скрипте позволяет Ansible выполнять задачи с правами root без прерывания сессии на ввод пароля.

- SSH: В ansible.cfg отключена проверка host_key_checking, чтобы избежать ошибок при первом подключении к новым серверам.

## Список хостов (Inventory)
Редактируйте файл inventory/hosts.ini для добавления новых серверов:

```
[webservers]
web-prod-01 ansible_host=1.2.3.4
web-prod-02 ansible_host=5.6.7.8
```
